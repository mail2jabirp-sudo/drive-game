# Netlify deployment

The game is a static Vite application. Netlify serves the compiled `dist` directory; no backend, paid asset service, runtime map API or application secret is needed.

## Source branch and history

The complete game and deployment files are now on **`main`**, advanced normally from the original map-only commit. The original game commits and uploaded map history are preserved. The earlier `codex/en3d-osm-kottakkal` branch remains available; no force-push or history replacement was used.

## Netlify settings

| Setting | Value |
| --- | --- |
| Repository | `mail2jabirp-sudo/drive-game` |
| Production branch | `main` |
| Base directory | Repository root; leave blank |
| Build command | `npm run build` |
| Publish directory | `dist` |
| Node.js | `24`, set in `netlify.toml` |
| Build image | Current Netlify image with Node 24 support and `python3` |

`netlify.toml` supplies the build command, publish directory, Node version and cache headers. Site branch selection and GitHub authorization are configured in Netlify, not by this file.

Keep development dependencies installed while building: TypeScript and Vite are needed. Do not set `NODE_ENV=production` or npm omit-dev settings during dependency installation. Commit and retain `package-lock.json`; Netlify installs the declared dependencies before running the configured build. The build's `prebuild` step checks the uploaded XML against the committed map excerpt with Python 3's standard library. There are no Python packages to install or runtime Python services. A specific Python 3.12 interpreter is not required; confirm `python3` in the selected Netlify build image on the first build. This environment was tested with Node 24.19 and Python 3.12.

No map regeneration is required on Netlify: the reproducible excerpt and provenance are committed. If the source is intentionally updated, regenerate and review it with `npm run map:import` before committing. The build rejects a stale excerpt.

## Asset paths and caching

The game is deployed at a site root. Vite's default base is `/`; the compiled HTML references fingerprinted JS/CSS in `/assets/`. Both areas use the root document with `?world=osm` or `?world=practice`. No client-side path router or catch-all rewrite is required.

`public/maps/kottakkal.json` and `public/maps/NOTICE.txt` are copied to `dist/maps/`. The game loads the local generated JSON, not the 12.9 MB source XML or an external OSM API. Original models, textures and audio are generated by the game; there are no external font/model/image downloads to configure.

Only fingerprinted `/assets/*` files have long immutable caching. `/maps/*` must revalidate because those filenames are stable between deployments. HTML retains Netlify's normal document revalidation behavior. Do not add a wildcard redirect that turns missing asset requests into HTML.

Keep the visible OpenStreetMap attribution and published data notice. Map data is ODbL 1.0, separately from the application's MIT code. See DATA_LICENSES.md.

## Verification performed before deployment

```sh
npm ci --cache .npm-cache
npm run build
npm run test:production
```

The production suite serves `dist` with Vite preview on port 4173 and checks every published file byte-for-byte, JS/CSS/JSON content types, the OSM source hash, license notice, and both compiled game areas. Browser checks exercise starting, throttle/brake, saves/reload, visible OSM attribution, and failed-asset/page-error detection. It does not use the Vite development server or transform source at request time. Chromium is needed only to run these local tests, not to run Netlify's build. Set `CHROMIUM_PATH` if Chromium is not at `/usr/bin/chromium`.

For an ordinary local production preview:

```sh
npm run build
npm run preview
```

This is local validation, not proof of a completed Netlify build or published site. Vite may emit its existing >500 kB bundle advisory; that is not a build failure.

## Remaining deployment steps

1. In Netlify, import the GitHub repository and authorize access using Netlify's own account flow. Select `main` and confirm the deployment uses its current game commit, not the historical map-only commit.
2. Check the root/build/publish settings above and use a current build image. Do not supply API keys: the current game does not need any.
3. Trigger the deployment and check the actual Netlify build log for dependency installation, Python map freshness check, TypeScript and Vite success. A first Netlify build has not been run from this workspace.
4. Open the resulting HTTPS site. Check the default welcome/start, both world choices, driving/mission UI, reload, touch controls and visible attribution. `/maps/kottakkal.json`, `/maps/NOTICE.txt` and the HTML's `/assets/` URLs must return their actual files without 404s or HTML substitutions.
5. Test on a real phone and, if desired, configure a custom domain in Netlify. Actual Netlify headers/build-image behavior, production network performance and real-phone FPS need validation on the published site.

Browser saves are scoped to the site's origin. A new Netlify domain has separate localStorage from localhost, the cloud preview or another domain. Existing saves are not deleted by this configuration, but they do not automatically transfer to a different origin.
